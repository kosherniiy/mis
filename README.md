# Miscrits Farmer

Модульный Windows-бот для автоматического прохождения повторяющихся боёв в Miscrits. Интерфейс распознаётся по PNG-шаблонам: жёстко заданных координат в проекте нет.

> Используйте проект только в личных целях. Автоматизация может противоречить правилам игры или сервиса. Ответственность за соблюдение этих правил лежит на пользователе.

## Дерево проекта

```text
farm2/
├── debug/
├── templates/
│   ├── map_wild_object.png
│   ├── close_info.png
│   ├── close_window.png
│   ├── lvl_up.png
│   ├── enchant.png
│   ├── evolve.png
│   ├── captured.png
│   └── battle_indicator.png
├── behavior.py
├── config.yaml
├── human_input.py
├── main.py
├── notifier.py
├── requirements.txt
├── screen_capture.py
├── session_manager.py
└── vision.py
```

Каталоги `debug`, `logs`, `encounters` и файл `state.json` создаются автоматически.

## Установка

Требуются Windows и Python 3.10+.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py
```

## Подготовка PNG-шаблонов

Создайте папку `templates` и нарежьте изображения при том же масштабе Windows, браузера/эмулятора и игры, при котором будет запущен бот. Используйте PNG без изменения размера и старайтесь захватывать небольшой, но уникальный фрагмент:

- `map_wild_object.png` — объект на карте, по которому начинается событие;
- `close_info.png` — крестик окна информации после боя;
- `close_window.png` — универсальный крестик окон;
- `lvl_up.png` — признак полученного уровня на экране результата боя;
- `enchant.png` — окно прокачки способности после повышения уровня;
- `evolve.png` — окно эволюции после уровня или новой способности;
- `captured.png` — окно успешной поимки мискрита;
- `character_up.png` — окно повышения персонажа после поимки;
- `achievment_ok.png` — кнопка подтверждения сообщения о достижении после боя;
- `battle_indicator.png` — стабильный элемент, видимый только во время боя.

Не включайте в шаблон анимацию, таймер, меняющиеся цифры или большой фон. Прозрачные поля тоже лучше обрезать. Если интерфейс меняет масштаб, подготовьте новый комплект PNG.

Отсутствующий или нечитаемый обязательный шаблон не завершает процесс исключением: ошибка записывается в лог, сохраняется снимок и после заданного числа пропусков включается `ERROR_PAUSE`.

Редкость определяется не шаблонами, а цветом одной точки клиентской области:

```yaml
rarity_pixel:
  x: 1266
  y: 57
  tolerance: 24
  colors:
    common: "#626262"
    rare: "#3366ff"
    epic: "#00cc00"
    exotic: "#cc00cc"
    legendary: "#ff9900"
```

Выбирается ближайший RGB-цвет. Если евклидово отклонение превышает `tolerance`, цвет считается неизвестным. Для проверки сохраняется `debug/rarity_pixel_*.png` с отмеченной точкой, фактическим цветом и отклонением.

На первом «Ваш ход!» бот при необходимости проверяет коллекцию, затем OCR читает вероятность поимки в области `(928,206)–(989,230)` и сохраняет скрин энкаунтера. Для редкого мискрита процент включается в ntfy-уведомление. Путь к Tesseract задаётся через `capture_chance_area.tesseract_cmd`.

Помимо редкостей из `stop_rarity`, бот останавливается на шансах из `stop_capture_chances` (сейчас `common` 27/30 и `rare` 17/20).

`--autoCatch` вместо паузы ослабляет мискрита сменой мувсетов и ловит его. Старт: 4-я атака 1-го мувсета. Перед каждой атакой OCR читает шанс поимки и HP; если шанс 100%, сразу «Ловить». Урон — разница HP до и после удара. Если оставшееся HP ≥ 2× этот урон, бьём той же атакой, иначе клик в `next_moveset_area` и переход к следующему мувсету (атаки 4 → 4 → 2). На последнем, самом слабом мувсете бьём, пока HP ≥ 1.5× урон этой атаки, затем ловим. Для мискритов ниже эпика проверка пикселя `catch_button_new_check` `(879, 168)` выполняется только на первом «Ваш ход!»: до атаки врага кнопка не мигает. За 1 секунду цвет снимается 5 раз каждые 0.2 с, и в коллекции он считается только если все 5 проб — один и тот же цвет без допуска. Если хоть одна отличается, мискрита ещё нет в коллекции, и его тоже ловят. Клик «Ловить» по-прежнему идёт в `catch_area`. При появлении `captured.png` отправляется уведомление вида «Пойман COMMON мискрит A+ Новый»: грейд считается по **начальной** вероятности поимки — для common 30 → `A+`, 27 → `S+`; для rare 20 → `A+`, 17 → `S+`. Иначе грейд не пишется. `Новый` добавляется, если пиксель поимки показал, что мискрита не было в коллекции. После такого боя бот проверяет `character_up.png` и при необходимости закрывает окно повышения персонажа той же областью, что и после эволюции. `--autoCatchAll` ловит каждого встречного мискрита, включая редкости из `stop_rarity`. `--autoCatchRares` ловит каждого rare, ordinary common по-прежнему только при `--autoCatch` (особый шанс или нет в коллекции).

`--lowLevelEncounters` в автоловле сразу переключает на 2-й мувсет (атака 4) вместо старта с 4-й атаки 1-го.

```powershell
python main.py --autoCatch
python main.py --autoCatchRares
python main.py --autoCatchAll
python main.py --lowLevelEncounters
python main.py --debugEncounters
```

`--debugEncounters` сохраняет скрин после первого «Ваш ход!» и OCR вероятности в `encounters/` с редкостью и процентом в имени файла.

Нужен шаблон `templates/captured.png`.

Атака нажимается без шаблона — в случайной точке выбранной безопасной области. По умолчанию циклически используется вторая:

```yaml
selected_attack: 2
attack_sequence: [2]
turn_prompt_area:
  left: 858
  top: 793
  right: 947
  bottom: 828
turn_check_interval:
  min: 1.0
  max: 1.5

attack_area_1:
  left: 324
  top: 862
  right: 639
  bottom: 979
  margin: 8

attack_area_2:
  left: 651
  top: 866
  right: 955
  bottom: 973
  margin: 8

attack_area_3:
  left: 963
  top: 860
  right: 1286
  bottom: 976
  margin: 8

attack_area_4:
  left: 1296
  top: 863
  right: 1610
  bottom: 976
  margin: 8

next_moveset_area:
  left: 1636
  top: 881
  right: 1684
  bottom: 957
  margin: 4

auto_catch_moveset_attacks: [4, 4, 2]
```

Координаты относятся к клиентской области окна. Отступ `margin` исключает клики по краям кнопки, а точки чаще выбираются ближе к её центру.
Каждые `1–1.5` секунды OCR проверяет надпись «Ваш ход!» в `turn_prompt_area`. Атака выполняется только при её обнаружении. Последовательность повторяется циклически: при смене номера атаки курсор перемещается в соответствующую область, а одинаковые соседние атаки выполняются без движения мыши.

Последовательность можно переопределить при каждом запуске:

```powershell
python main.py --attack 1
python main.py --attack 1,2,2
python main.py --attack 4,3,2,1
```

Стартовую фазу можно выбрать отдельно:

```powershell
# Обычный запуск с поиска объекта
python main.py --phase search

# Начать с уже открытой кнопки «Далее» после прокачки
python main.py --phase lvl_up_continue

# Начать с уже открытого окна «Повышение» после эволюции
python main.py --phase character_promotion
```

По умолчанию используется `start_phase: "search"` из `config.yaml`. Фаза `lvl_up_continue` нажимает «Далее», выполняет одиночные проверки `evolve → enchant → evolve`, закрывает окно опыта и только затем обрабатывает ожидающее окно «Повышение». Фаза `character_promotion` начинает с нажатия уже открытой кнопки «Повышение».

Чтобы при успешном запуске отправить сообщение в настроенную тему ntfy:

```powershell
python main.py --notifyStart
```

Также поддерживается вариант `--notify-start`. При перезапуске бот сохраняет аргументы запуска, поэтому уведомление будет отправлено повторно.

Объект карты ищется по `map_wild_object.png` один раз. После первого наведения координата фиксируется: если бой не начался, бот без повторного поиска и без движения мыши кликает в ту же точку через случайный интервал `4–6` секунд, максимум `max_map_click_attempts` раз (по умолчанию 20). После каждого клика проверяется `battle_indicator.png`.

Если `map_wild_object.png` не найден пять поисков подряд, бот считает, что карту перекрыло окно достижения, кликает локальную точку `(942,665)`, сбрасывает счётчик пропусков и продолжает поиск. Порог и координаты находятся в `map_achievement_close`.

Количество атак не ограничено. После каждой атаки проверяется пиксель завершения боя. При точном совпадении бот нажимает случайную точку кнопки «Далее»:

```yaml
battle_result_pixel:
  x: 962
  y: 305
  color: "#b6c8e1"
  tolerance: 0

continue_area:
  left: 863
  top: 839
  right: 1057
  bottom: 903
  margin: 8
```

Перед нажатием «Далее» бот ищет `lvl_up.png` на том же снимке результата. Если шаблон найден, после закрытия окна результата выполняется переход к прокачке; иначе бот сразу возвращается на карту.

## Калибровка confidence

Начните с:

```yaml
confidence_threshold: 0.85
debug: true
```

В `debug/` сохраняются снимки с зелёной рамкой и фактическим confidence. Если правильный элемент стабильно имеет значение ниже порога, уменьшайте порог шагами по `0.02`, например до `0.83`. Если бот путает похожие элементы, увеличьте порог или вырежьте более уникальный шаблон. Обычно не стоит опускаться ниже `0.75`.

Перед полноценным запуском проверьте по логам все состояния и координаты на нескольких ручных боях. При смене разрешения, DPI или масштаба браузера откалибруйте шаблоны заново.

## Настройки

Заголовок окна:

```yaml
window_title: "Miscrits"
```

Чтобы узнать точный заголовок, откройте игру и выполните в PowerShell:

```powershell
Get-Process | Where-Object {$_.MainWindowTitle} |
  Select-Object ProcessName, MainWindowTitle
```

Поиск сначала проверяет точное имя, затем совпадение по части заголовка.

Автоматическая прокачка включается так:

```yaml
level_up:
  enabled: true
```

В конце боя вместе с `lvl_up.png` бот проверяет пиксель HP `(520, 403)`. Цвет, близкий к `#2F3B47` с допуском `heal_check_pixel.tolerance`, означает необходимость лечения. После боевого «Далее» и повторно после закрытия окна «Опыт» бот один раз проверяет `achievment_ok.png`. При совпадении сообщение подтверждается кликом внутри `achievement_ok_area`.

Если level-up не требуется, но обнаружена необходимость лечения, бот после закрытия сообщений нажимает `heal_area`, ожидает окно подтверждения и нажимает `heal_confirm_area`. При наличии level-up отдельное лечение пропускается.

После обнаружения `lvl_up.png` бот открывает вкладку «Опыт», проверяет цветовые маркеры четырёх мискритов, последовательно прокачивает отмеченных жёлтым и закрывает окно опыта. Координаты областей и эталонные цвета находятся в `config.yaml`.

После каждого прокачанного мискрита `enchant.png` проверяется один раз. При появлении окна способности бот подтверждает его случайным кликом внутри `enchant_area`, после чего продолжает прокачку оставшихся мискритов.

Проверки выполняются строго по одному разу в порядке `evolve.png` → `enchant.png` → `evolve.png`. При совпадении окно эволюции закрывается кликом по локальной точке `(945, 886)`, а счётчик окон «Повышение» увеличивается. Бот сначала закрывает окно «Опыт», затем кликает область `(890,724)–(1027,783)` столько раз, сколько эволюций было в этой прокачке.

Остановка на редком мискрите управляется параметрами:

```yaml
stop_on_epic_plus: true
stop_rarity: ["epic", "legendary"]
```

В состоянии `STOPPED_EPIC` игровые клики прекращаются, сохраняется `debug/epic_stop_*.png`, а процесс ожидает перезапуска или `Ctrl+C` без звукового сигнала.

## Состояние, логи и остановка

- Логи выводятся в консоль и сохраняются в `logs/`.
- Ожидания не записываются в лог; основной файл содержит действия, переходы состояний, предупреждения и ошибки.
- `state.json` содержит состояние, последние координаты, счётчики и расписание сессии.
- Короткие перерывы и ежедневный сон отключены.
- `NUMPAD *` ставит бота на паузу и повторным нажатием продолжает работу. При паузе запоминается позиция курсора; перед продолжением курсор плавно возвращается в неё.
- Резкое ручное перемещение мыши минимум на `manual_mouse_pause.jerk_threshold_px` пикселей за один интервал проверки также включает паузу. ПКМ по окну Miscrits снимает только эту ручную паузу и возвращает курсор в точку до рывка.
- `Alt + NUMPAD *` сохраняет состояние и перезапускает бота с теми же аргументами запуска.
- СКМ по окну Miscrits также сохраняет состояние и перезапускает бота.
- При остановке игровой логики, включая превышение лимита ошибок, процесс остаётся запущенным и продолжает принимать команды перезапуска.
- ntfy-тема `miscrits_farm_goldmonster` получает уведомления при остановке на редком мискрите, превышении лимита ошибок и критической ошибке верхнего уровня. Настройки находятся в секции `ntfy`.
- Для корректной остановки нажмите `Ctrl+C`. Бот завершит текущий обработчик, сохранит состояние и освободит захват экрана.

Если клики не проходят в эмулятор, запустите терминал с теми же правами, что и игра. Не запускайте игру или терминал от администратора без необходимости.
